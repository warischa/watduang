Pick 12 at a glance · which screen loses which heading element

The page h1 is h1.game-title, rendered by GameLayout.astro from game.names.th. The stage heading is whatever the game module builds inside #stage. Result reveal (pick 5) · where it happens, start and end frame · 390

Every result is a screen swap inside #stage: the module clears the stage with replaceChildren() and appends the result in one task, under the finger that pressed. So the reveal happens in place, in the same box the previous screen occupied, and the stage grows downward. Each row reads A (the screen the finger is on), B (start frame: the dashed outline is the final box of the result element, content hidden; what is painted at the start is a motion value), C (end frame: settled). Pick 12 only changes screen 1 of siamsi and love-match, so none of these frames depend on it. motion: see Gh288MotionSheet § result reveal (duration, easing, distance and the reduced form are there and nowhere in this file).

Constraint · arm window. Every one of these renders ends with armAllButtons(stage) (src/games/_arm-gate.ts). That keeps the result screen's controls disabled for ARM_DELAY_MS = 400 ms, so a second contact of a double-tap cannot activate what the reveal just put under the finger; closing a modal arms the same way (ADR-0057). The reveal must therefore be settled within 400 ms: at that moment the controls become tappable, and a result still moving would put a live button under a moving layout. Dropping a heading arms nothing. The removed elements are not controls, armAllButtons never saw them, and pick 12 changes no render call and no timer. Adding the reveal also arms nothing: the gate is already attached to every one of these renders.

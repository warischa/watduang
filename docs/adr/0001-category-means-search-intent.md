# หมวดของเกมแบ่งตามเจตนาของคนค้นหา ไม่ใช่ตามกลไก

`category: 'party' | 'fortune'` ถูกประกาศไว้ใน `src/games/types.ts` ตั้งแต่ #13 โดยไม่มีคำนิยามอยู่ที่ไหนเลย และมันกำลังจะแตก เพราะ `pick-loser` กับ `short-straw` ถูกจัดเป็น `party` ทั้งที่กลไกข้างในคือการสุ่มผลแบบเดียวกับ `siamsi` ที่เป็น `fortune`

เราตัดสินว่า **หมวดคือเจตนาของคนค้นหา** — `fortune` คือ "คนพิมพ์ดูดวง มาหาคำตอบเกี่ยวกับตัวเอง" ส่วน `party` คือ "คนพิมพ์สุ่มคนโดน มาหาเครื่องมือตัดสินให้วง" ไม่ใช่ "สุ่มผล vs ใช้ทักษะ"

## เหตุผล

หมวดในเว็บนี้ไม่ใช่ป้ายกำกับทางเทคนิค มันจะกลายเป็นหน้า `/c/<category>/` ที่ต้องไปยืนใน SERP ให้ใครสักคน ถ้าจัดตามกลไก หน้าหมวดจะรวมของที่คนละเจตนาไว้ด้วยกันแล้วไม่ตอบใครเลย — คนที่พิมพ์ "ดูดวง" กับคนที่พิมพ์ "สุ่มคนโดน" คือคนละคนที่มาด้วยคนละความต้องการ แม้โค้ดข้างในจะเรียก `Math.random()` เหมือนกันก็ตาม

## ผลที่ตามมา

แกนกลางของเว็บ (ดูใน `CONTEXT.md`) คือ **ดวงตัดสิน** ซึ่งครอบทั้งสองหมวด — หมวดจึงไม่ได้บอกว่าเกมทำงานยังไง บอกแค่ว่าใครควรเจอมัน การจัดหมวดเกมใหม่ต้องเริ่มจากคำถาม "คนที่จะเล่นเกมนี้พิมพ์อะไรลงไปค้น" ไม่ใช่ "เกมนี้สุ่มหรือเปล่า"

หมวดที่จัดตามกลไกจะให้ผลต่างออกไปอย่างมีนัย: `timebomb` ยังเป็น `party` แต่ `pick-loser` จะกลายเป็น `fortune` ซึ่งขัดกับตาราง 7 เกมใน #5 — เราปฏิเสธผลลัพธ์นั้นโดยตั้งใจ

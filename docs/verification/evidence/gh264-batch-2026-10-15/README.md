## Notes on method and coverage
- A: stepper bounds were measured by tapping + / - to the disabled state and compared with the literal range in src/games/<id>.ts (all match). Rows: 4 mascot emoji in ADR-0054 order. The round-start chain per route = the route own intro/option/ready taps (e.g. dice-loser #dl-begin, how-close-is-near #btnStartGame then #btnAckSecrecy, zero-trigger #btn-confirm-start-game). Seat names visible in the round are in results-390-ABCD.json (A.names); several routes show only the current player, the 4 names are the written watduang:group value.
- B: reload with storage kept; no stepper, 4 ticked rows with x, one start press; the buttons of the first screen after start equal A first screen after start.
- C: dialog title/body/cancel/confirm text compared with the board copy (design/PlayerSetup.dc.html). Cancel and confirm each followed by a second tap at the same point 50 ms later, then state compared (cancel: identical to pre-dialog state; confirm: screen open, 4 ticked rows, no round).
- C coverage limit, measured in results-C-under-point-control.json: the point under the cancel/confirm button after close is an inert element on 12 of 14 routes (cancel) and 9 of 14 (confirm), so the same-point second tap proves little there. Reactive under-points: cancel on one-bomb and short-stick; confirm on one-bomb, short-stick, zero-trigger (add-row), power-meter and croc-bite (start). A tap 1000 ms later does change state there, so the 50 ms no-op is a real discrimination on those. Added stronger probe (results-C-fast-start-tap.json): after confirm, tap [data-ps=start] 3-131 ms after the confirm tap: start is disabled in that window on all 14 routes (screen stays open), and a later tap starts the round. Not exercised: a second tap 50 ms after CANCEL on a reactive round control, on the 12 inert routes.
- D: row 2 name set via native value setter + input event after a real tap on the field; dup line equals frame 9 copy, rows 1-2 carry .ps-dup, start disabled; renaming row 2 re-enables start.
- 320: saved roster of 3 (ต้น, มายด์, บอส) seeded; shared screen and one in-round screen per route; document.scrollWidth equals innerWidth on all 28 captures; start control reachable (scrolled into view, inside 0..320, elementFromPoint is the control, tap starts the round) on all 14.
- Ruling 4 (croc-bite max 6): cursed-number stepper to 8, start; croc-bite then shows 8 rows, 6 ticked, 2 .ps-out with tag นั่งพัก, line "เกมนี้เล่นได้สูงสุด 6 คน · เลือกแล้ว 6", start enabled; after start watduang:group holds the first 6, watduang:roster still 8. Raw: results-320-and-croc-ruling4.json. PNG croc-bite-ruling4-8names.png. Not run: roster above 8 or the frame-10 roster-full line.
- Not reached/not asked: no route has max below 4, so the clamp-to-range of the 4 default was not exercised below the default.

## Findings
- F1 (FAIL, touch): cannon-flag, any viewport. A CDP touch tap (touchStart+touchEnd) on any button, e.g. [data-ps=inc] or [data-ps=start] on the shared screen, yields pointerdown/touchstart/pointerup/touchend and NO click, so nothing activates. Cause (read from source): src/play/cannon-flag/main.js registers window touchend (passive:false) -> releasePowerCharging, which calls preventDefault on every touchend, suppressing the click for all buttons. The same listener exists at 219fe98^ (before the gh#264 cannon-flag commit), so pre-existing, not introduced by this batch; it is unconfirmed on a real phone. Mouse input (used for the cannon-flag column) works.
- V1 (visual, not gated): short-stick (light theme) renders the shared screen with smaller/thinner type than the other routes (reset label, stepper count, start label, dialog buttons), see short-stick-A1-first-visit.png and sheet-C1-edit-dialog-2.png (4th tile).
- V2 (visual): at 320 the edit-players pill overlaps route chrome in one-bomb and croc-bite (HUD chips) in-round, see sheet-W320-2-round-1.png (4th tile) and sheet-W320-2-round-2.png (7th tile); in wire-snip-panic the player-card badge row is clipped at the right edge (badge right 335 > 320, no page scroll).
- V3 (visual): at 320 pinocchio-luck the close X sits on its title badge (sheet-W320-1-shared-2.png, 2nd tile).

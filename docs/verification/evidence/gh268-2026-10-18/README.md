## Method
- Route set from the manifest, not a hand list: `node --input-type=module -e 'import {games} from "./src/games/manifest.ts";console.log(games.filter(g=>g.playRoute).map(g=>g.id).join("\n"))'` printed **14**: timebomb, one-bomb, short-stick, freeze-tap, cannon-flag, power-meter, dice-loser, how-close-is-near, pinocchio-luck, cursed-number, wire-snip-panic, zero-trigger, bangkok-drift, croc-bite.
- Build: `dist/` present and newer than every file under `src/` (`find src -newer dist/index.html` empty), so no rebuild. `npx serve dist/ -l 4441`; Chrome 155 `--headless=new --use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader --no-sandbox --remote-debugging-port=9441` with its own profile dir. No `--disable-gpu`, so WebGL routes run their real board (one-bomb in-round shows `#turnBanner`, not the no-3D fallback; the WebGL context itself was NOT read in-page this run).
- Viewport via CDP `Emulation.setDeviceMetricsOverride` 320x568, deviceScaleFactor 2, mobile true; `innerWidth` and `documentElement.clientWidth` both read 320 on every record.
- `measure.mjs` (own CDP client, not `scripts/driver.mjs`, which pins deviceScaleFactor 1). Per route: S1 = first visit, empty storage, route as loaded. S2a = saved roster of 3 (ต้น, มายด์, บอส) seeded on-origin, reloaded, shared player screen open (the three routes whose first screen is their own menu get one click first to open it). S2 = after the shared screen's `[data-ps=start]` and then the route's own begin-the-round control (map in the script; each id probed per route). S2 is the first in-round screen, not a late-round one.
- Per control: rect, z-index, then every body element with a non-zero rect, `visibility` visible, own AND ancestor-product opacity > 0 (a closed overlay hides itself with opacity 0 on an ancestor; the first pass without this counted power-meter's closed help modal, a false 1143 px2 hit, and was discarded), not an ancestor/descendant of the control, intersecting the control after clipping by overflow ancestors. Elements covering >= 90% of the viewport are ignored and counted (column "full-screen ignored"). Intersection area, share of the control, and `document.elementFromPoint` at the intersection centre (tap winner). Each hit is flagged `content` (leaf, direct text, or button/img/canvas/svg/input/anchor) vs container box; the table and counts use `content` hits only; containers are in the JSON.
- Control hidden by design: `#play-edit-players` is `hidden` while the shared player screen is open, so it is measured only where it is shown.

## Aggregate (14 routes; content overlap > 0)
- `#play-exit` (shown everywhere): S1 2 of 14 routes (one-bomb, pinocchio-luck), S2a 2 of 14 (same), S2 4 of 14 (one-bomb, pinocchio-luck, bangkok-drift, croc-bite).

- Tap winner: the control wins at the centre of every top overlap; elsewhere the chip wins where the control's rounded corner leaves it (one-bomb turnPlayerName, audioToggleBtn).

## Limits
- Programmatic `.click()` for navigation only; no real touch. Real iOS WebKit not covered. One roster size (3 names) and one viewport (320x568). n=1 per route x state except one-bomb n=3 plus the main run.
- "Round started" is the first in-round screen after the route's own begin control; later screens (long names, 10 players, mid-round modals) were not walked. bangkok-drift S2 shows a running HUD with no buttons besides the site controls.
- The 90% full-screen filter counts but never lists backgrounds; a canvas covering the control (cannon-flag `#game-canvas`, 100%) is content, not ignored, because it is under 90% of the viewport.
- No fix or layout proposal (out of scope).

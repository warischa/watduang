## #18-10
issue: 18 (สุ่มเลข /tool/number/)
text: เคารพการตั้งค่าลดการเคลื่อนไหว และผลลัพธ์อ่านได้จากตัวหนังสือเสมอ
verdict: UNDECIDED

Two independent assertions, each verdicted on its own per the coordinator's rule
(box verdict = weakest of the assertions):

- **"เคารพการตั้งค่าลดการเคลื่อนไหว" (respects reduced-motion setting) — UNDECIDED.**
  Grepped `src/pages/tool/number.astro`, `src/layouts/Base.astro`,
  `src/styles/tokens.css` for `transition`/`animation`/`@keyframes` — zero matches;
  this tool has no motion-dependent CSS at all. The playbook says verbatim: "a page
  with no animation at all is N/A, not pass — do not record a non-existent animation
  as a passing check." First draft of this report tried to upgrade past that with a
  `getComputedStyle` scan (`animationName !== 'none' || transitionProperty !== 'all'
  && transitionProperty !== 'none'`) that returned `0` matches under both
  `matchMedia` states. That upgrade doesn't hold: the boolean parses as
  `A || (B && C)`, so an element with `transition: all 0.3s` — a real, motion-bearing
  transition — has `transitionProperty === 'all'`, making `B` false and the element
  **uncounted**. I never ran this probe against a known-animated element (a positive
  control), so I cannot say it would have caught a real violation; the `matchMedia`
  half was calibrated both ways, but the animation-count half was not. No external
  party owns this claim — everything needed to check it is already in `dist/` — so
  it is not UNPROVABLE. It is a case where the available proof (grep + an
  uncalibrated probe) doesn't discriminate a pass from "nothing to test," and I
  cannot honestly call it either PROVEN or FAILED. Unblocking: recalibrate the probe
  against a page/element with a genuine `transition`/`animation` (positive control),
  confirm it correctly flags that as non-zero under `matchMedia: false` and zero (or
  correctly paused) under `matchMedia: true`, then rerun.
- **"ผลลัพธ์อ่านได้จากตัวหนังสือเสมอ" (result always readable as text) — PROVEN.**
  After a real draw, `#number-result`'s `firstChild` is `nodeType: 3` (a genuine DOM
  text node) with content `ได้: 1`/`ได้: 4` etc., and the element carries
  `role="status"` `aria-live="polite"` — plain text, not a canvas/image/animation-only
  presentation, exposed to assistive tech.

Weakest of the two assertions (UNDECIDED, PROVEN) → box verdict **UNDECIDED**.

Evidence: `../evidence/18/10-reduced-motion-on.json`, `../evidence/18/10-reduced-motion-off.json`.
